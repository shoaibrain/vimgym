# Vimgym v0.2.0 product and architecture contract

Status: implemented Beta contract; release gates remain authoritative.

## Release promise

Vimgym v0.2 upgrades v0.1.1 vaults without data loss, keeps growing Claude
and Codex sessions current, exposes one provider-neutral lexical search and
browsing model, and creates verified portable whole-vault backups.

Complete capture means redacted user-visible text, tool calls and results,
visible provider summaries, file activity, metadata, and parent/root lineage.
Binary attachments retain metadata only. Hidden/encrypted reasoning, provider
telemetry, world state, inter-agent transport, and native unredacted JSONL are
excluded.

Supported read-only roots are:

- Claude Code projects, root session JSONL, actual subagent JSONL, and referenced
  textual `tool-results` sidecars.
- `$CODEX_HOME/sessions/**/*.jsonl` and
  `$CODEX_HOME/archived_sessions/**/*.jsonl`, including user tasks,
  automations, and subagents.

Multiplexed Claude workflow `journal.jsonl` files are coordination transport
that duplicate the actual per-agent JSONL and contain multiple agent identities;
they are excluded rather than misattributed. Codex memories, logs, goals, state,
auth/config databases, and import maps are never discovered.

## Locked non-goals

- Hosted services, cloud/S3 sync, accounts, telemetry, and collaboration.
- Backup encryption, native raw archives, scheduling, or retention policies.
- Vector search, embeddings, generated decision summaries, tags, or cost views.
- Cursor, Copilot, Gemini, Windows, writeback/replay, or a public plugin SDK.
- A frontend framework migration or broad visual redesign.

## Canonical vault

`PRAGMA user_version=2` and `schema_migrations` version the vault. The canonical
tables are:

- `sources`: configured provider roots, enablement, freshness, and bounded
  health diagnostics.
- `workspaces`: provider plus canonical working-directory identity.
- `sessions`: provider/external identity, kind, lifecycle, lineage, originator,
  client/model, title, workspace/branch, times, versions, revision, and health.
- `source_artifacts`: source-relative path, stat/hash state, lifecycle,
  parser/policy versions, processed bytes/lines, status, and diagnostics.
- `messages` and `message_blocks`: deterministic source-sequence conversation
  records and `text`, `tool_call`, `tool_result`, `attachment`,
  `reasoning_summary`, `compaction`, `omitted`, or `unknown_event` blocks.
- `message_fts`: visible redacted block text, with relational IDs unindexed.
- Derived `session_tools` and `session_files`.

The v1 `sessions_raw` and aggregate `sessions_fts` tables are removed after
migration validation. Legacy Claude-facing columns remain only for the v0.2
identifier/response compatibility window and never contain provider-native raw
records.

Session IDs are UUIDv5 over `provider + external_session_id`. Provider plus
external ID is unique. Message IDs prefer provider-native identity and otherwise
use source line/item position; block IDs extend the message identity. Ordering is
source sequence, not timestamps. Active-to-archived Codex movement changes the
same session/artifact. Claude child identity is root ID plus `agentId`.
`originator` is separate from storage provider, representing cases such as
“Claude Cowork via Codex” honestly.

Provider titles are preferred; otherwise the deterministic redacted first-user
preview is used. v0.1 generated summaries are not carried into v0.2.

## Built-in adapter boundary

`vimgym.providers.ProviderAdapter` is an internal registry, not a third-party
plugin system:

```python
default_sources(environment) -> list[SourceSpec]
iter_artifacts(source) -> Iterable[ArtifactCandidate]
probe(artifact) -> ArtifactIdentity
parse(artifact, sink) -> ParseOutcome
```

Adapters stream `CanonicalSession`, `CanonicalMessage`, and `CanonicalBlock`
records. `RecordSink` is the privacy boundary: production ingestion recursively
redacts each record, wraps it in `RedactedRecord`, and only then writes temporary
staging rows. Persistence does not accept an unwrapped canonical record.

Claude mapping covers user/assistant/system, titles/prompts, queue/mode,
attachments/PR links, file history, tool calls/results, subagent lineage, and
text sidecars. Hidden thinking and binary payloads become metadata-only omitted
blocks.

Codex treats `response_item` as authoritative for messages/tools and uses
`event_msg` for lifecycle/usage or compatibility fallback. Known duplicate
representations normalize once. Visible reasoning and compaction summaries are
retained; timing/rate-limit/world-state/inter-agent telemetry is ignored with
counters. Structured `thread_source` and `parent_thread_id` determine kind and
lineage. Unknown content-bearing records become hidden redacted `unknown_event`
blocks and degrade health; telemetry-only records are counted and ignored.

## Revision-aware ingestion

One daemon-wide bounded coalescing queue and one worker replace per-path timer
threads. Startup reconciliation always runs.

1. Wait for the five-second default stability debounce.
2. Skip an artifact when size, mtime, parser version, and redaction-policy hash
   are unchanged.
3. Hash changed content with constant memory; skip metadata-only touches with an
   identical hash.
4. Stream complete JSONL lines through redacting temporary staging tables.
5. Defer an incomplete trailing line and mark the artifact partial/degraded.
6. Validate one session graph, message/block references, counts, and diagnostics.
7. Atomically replace only that artifact's previous contribution, update derived
   FTS/tools/files, and advance the session revision.
8. Roll back a failed parse/write and retain the last valid canonical revision.
9. Publish `session_created`, `session_updated`, or `session_archived` after
   commit; health changes use `source_health_changed`.

v0.2 deliberately reparses a changed artifact in full. Byte-offset append
parsing is deferred until measured release benchmarks demonstrate it is needed.
Missing provider files become `missing`; retained vault history is not deleted.

## Privacy and loopback security

Redaction covers titles/fallback titles, every role's text, tool arguments,
results/errors and structured strings, display paths/CWD/branch, attachment
names, visible summaries, diagnostics, FTS, APIs, WebSockets, exports, and
backups. Stable IDs, timestamps, hashes, and configured source roots are
operational metadata.

Invalid, malformed, or empty policies fail closed. The byte-deterministic policy
hash is persisted on artifacts/sessions and forces reindex after a change.
Credential scrubbing is not anonymization; vaults and backups remain sensitive.

Search returns `snippet_parts: [{text, matched}]`. The UI creates text nodes and
contains no untrusted HTML insertion sink. Assets/fonts are local. HTTP responses
ship a restrictive self-only CSP, MIME sniffing/frame/referrer protections, and
no-store API caching.

Configuration accepts only `127.0.0.1`, `localhost`, or `::1`. HTTP Host and
browser Origin and WebSocket Host/Origin are validated. No bearer token is added
because the service cannot bind publicly.

## Migration and rollback

Before watcher or server startup, the daemon serializes migration with an
owner-only lock and creates an owner-only SQLite online rollback snapshot.
Migration rebuilds provider-neutral IDs, recursively re-redacts v1 titles and
message JSON, splits blocks, rebuilds block FTS, preserves legacy UUIDs,
timestamps, tools/files/tokens/provenance, and marks source artifacts
`needs_reindex`.

Migration validates row counts, fixed FTS availability, `integrity_check`, and
`foreign_key_check`; it then vacuums/checkpoints deleted v1 raw pages. A failure
rolls back the transaction, while a post-commit validation failure restores the
snapshot before startup. Future schema versions fail without mutation. There is
no down migration: operational rollback restores the v1 snapshot and reinstalls
v0.1.1.

## Local interfaces

CLI additions:

```text
vg search QUERY --provider --session-type --lifecycle
vg reindex [--provider PROVIDER] [--session ID]
vg backup create DEST
vg backup verify ARCHIVE
vg backup restore ARCHIVE --to VAULT_DIR [--replace]
vg doctor --json
```

HTTP contracts:

- `GET /api/sessions`: provider/source/kind/workspace/branch/lifecycle/date
  filters, opaque `(started_at,id)` keyset cursor, default 50/max 100.
- `GET /api/sessions/{id}`: metadata only.
- `GET /api/sessions/{id}/messages`: sequence cursor, default 100/max 200 and a
  hard response budget below 2 MiB.
- `GET /api/message-blocks/{id}`: explicit full redacted oversized content.
- `GET /api/search`: block FTS, matching filters, structured snippets, default
  20/max 100, and rank/message/block keyset cursor.
- `GET /api/sessions/{id}/export?format=markdown|canonical-jsonl`: bounded
  streamed provider-neutral export.
- `/ws`: the four committed event types above.

Blocks larger than 64 KiB use an 8 KiB preview and `content_url`. Existing
Claude UUID prefixes remain accepted; ambiguity returns 409. `session_uuid` is a
deprecated Claude-only alias. `/raw` is removed.

## Portable backup

`vimgym-YYYYMMDDTHHMMSSZ-v2.vgbak` is an owner-only ZIP containing
`manifest.json`, a consistent `vault.db`, `config.json`, and optional custom
`redaction-rules.json`. The manifest records format/app/schema versions,
creation UTC, canonical counts, sizes, and SHA-256 hashes.

Creation uses `sqlite3.Connection.backup()`, validates SQLite and member hashes
in a temporary sibling, fsyncs, and atomically publishes. Restore requires the
daemon stopped, rejects duplicate/traversal/unexpected paths and unsupported
schemas, verifies every byte before destination mutation, restores through a
temporary sibling, and atomically swaps. Non-empty replacement needs
`--replace` and creates a rollback backup first. Restore is whole-vault, not
merge. Missing provider roots are disabled/reported while history stays usable.

## Release evidence

PR gates cover Ruff, MyPy, ShellCheck, fixture leak scanning, Linux/macOS on
Python 3.11–3.14, migration/revision/redaction/security/backup contracts,
installed-wheel smoke, and coverage. Nightly/release candidates add deterministic
100 MiB/25,000-message performance, long-running watcher/restart reconciliation,
cross-platform restore, minimum/latest dependency resolution, and `pip-audit`.

No waiver is permitted for data loss, secret leakage, stored XSS, non-loopback
exposure, migration recovery failure, backup corruption, or release artifact
mismatch. Release artifacts are built once, hashed/attested, and the identical
bytes are published to PyPI and GitHub. Tags and published assets are immutable;
recovery never clobbers or rebuilds a published version.
